## Why

The `run` MCP tool is the single execution path every OneTool call travels — command normalization, execution, result serialization, and (when servers are proxied) MCP result conversion. A four-way deep code trace (`wip/release-v3/core-flow-deep-dive.md`, verified against `main`@`151a52b3`, FastMCP 3.3.1) found 15 numbered defects (D1–D15) plus 10 lower-severity items (D-a1–D-a4, D-b1–D-b3, D-c1) and 4 compliance findings (F3–F4, an annotations nit) in that exact path. One is a **reproduced hard crash on an everyday input** (any string with both an apostrophe and a newline). One is an **MCP-spec compliance defect**: every tool-execution failure — validation errors, user-code exceptions, snippet errors — is returned as `isError:false`, so a client/agent branching on `isError` cannot distinguish success from failure. Others silently corrupt or drop correct results (surrogate crashes, NaN/Infinity emitting invalid JSON, a "successful" result reported as an execution error, a proxied tool's structured payload silently dropped, a string result force-coerced to the wrong type) or freeze the whole server on ordinary blocking calls. The report's independent architecture/performance review (R8 P1–P4) additionally found the shared `otpack` memoize cache is unbounded (steady-state RSS leak) and the registry double-parses every tool file's AST at startup. Fixing this now, in the V3 breaking window, closes the gap between "the base design is sound" (confirmed — see Verified-Good Baseline in design.md) and "the implementation matches the design everywhere," before more surface area is built on top of it.

## What Changes

- **BREAKING (MCP response contract)**: `run()` now raises `fastmcp.exceptions.ToolError` when `prepared.error` is set or when `execute_command` returns `success=False`, instead of always returning a `ToolResult`. Every tool-execution failure now surfaces as `isError:true` with the error text preserved in the exception message. Works against installed FastMCP 3.3.1 — no version bump required. (D2)
- Guard `_force_single_quotes` against control characters and wrap both the normalization step and all of `prepare_command` so a crash inside preparation can never escape the `run` tool handler. (D1)
- User code (the `execute_python_code` call inside `execute_command`) now always runs via `asyncio.to_thread`, regardless of whether any proxy server is connected, so a blocking tool call no longer freezes concurrent `run`/`ping`/cancellation. `connect_additional_sync` and `disconnect_server_sync` gain the same same-loop guard `reconnect_sync` already has, closing a deadlock where a server-control call issued from inline user code could block on its own event loop for up to 120s. A bounded per-tool execution timeout is added. (D3)
- `resolve_kwargs` refuses ambiguous/colliding parameter targets (an exact match and a prefix match landing on the same real parameter) instead of silently letting dict-iteration order pick a winner and discard a correct value. (D4)
- Nested `__onetool(...)` execution runs in a child namespace with the three output magics (`__format__`, `__sanitize__`, `__force_context__`) snapshotted and restored around the nested `exec`, so a nested command can no longer leak its magics or ordinary variables into the outer result. A recursion-depth guard is added for nested calls, and nested error line numbers account for the correct line offset. (D5, D-a2, D-a4)
- The real exception type is preserved end-to-end: the wrapped runtime-error message includes `type(e).__name__`, and `CommandResult.error_type` carries the original type instead of always reporting `ValueError`. (D6)
- `serialize_result` scrubs lone UTF-16 surrogates at the serialize boundary instead of crashing on `.encode("utf-8")`; uses `json.dumps(default=str, allow_nan=False)` so non-JSON-native values (datetime, Decimal, set, bytes, Path, custom objects) degrade to a string representation instead of being reported as an execution error, and NaN/Infinity degrade instead of emitting invalid JSON; YAML formats (`yml`/`yml_h`) switch to `yaml.safe_dump` with a fallback representer so unsafe `!!python/object` tags are never emitted; and the emitted format label matches what was actually produced when a top-level value falls through to `str()`. (D7, D8, D9, D10, D-b1)
- `TRIGGER_PATTERN` in output sanitization is tightened so prose mentions of `__ot`/`__onetool` (e.g. "see `__ot` for details") are no longer redacted — only the invocation shape (token followed by `.`/`(`) triggers redaction. (D11)
- Trusted error `CommandResult`s and `prepare_command` errors are sanitized consistently (both `should_sanitize=False`, since first-party error text should not be boundary-wrapped or trigger-redacted); large-output deflection sanitizes before storing to `ctx` and preserves the caller's requested output format instead of always re-serializing as JSON. (D-b2, D-b3)
- Empty/whitespace-only commands now return an explicit validation error (`prepared.error`) instead of silently reporting success with no return value — a deliberate decision recorded in design.md. (D-a1)
- The MCP proxy result-conversion loop (`ProxyManager.call_tool`) now handles `types.EmbeddedResource` content blocks and falls back to `structured_content`/`.data` when `content` yields nothing, instead of reporting "Tool returned empty response." JSON coercion of single text results is restricted to text that structurally looks like JSON (starts with `{`/`[`); a proxied tool that returns a plain string (e.g. `"007"`) is no longer force-parsed into a different type. (D12, D13)
- `pack_proxy`'s per-server namespace cache (via `McpProxyPack._function_cache`) and `param_resolver`'s `_mcp_param_cache` are evicted for the affected server inside `connect_additional`, `disconnect_server`, and `reconnect`, so a `restart` (disconnect immediately followed by connect of the same server name) can no longer serve stale tool-name/parameter resolutions after a downstream schema change. (D14)
- `ProxyManager.list_tools(server=None)` snapshots `_tools_by_server` under `_mutation_lock` before iterating, removing a `RuntimeError: dictionary changed size during iteration` race between a full-scan read and a background connect. (D15)
- `call_tool_sync`'s cancel path calls `future.cancel()` on timeout instead of leaking the scheduled `run_coroutine_threadsafe` future. (D-c1)
- A regression unit test asserts the `run` tool's `output_schema is None` (protects the load-bearing `-> ToolResult` return annotation) with an explanatory comment. (F3)
- The Direct API's `uvicorn.Config` passes `log_config=None` so uvicorn's default `dictConfig` can never install a stdout `StreamHandler` that could corrupt the stdio JSON-RPC stream if the log level is ever lowered. (F4)
- `run`'s tool annotation `destructiveHint` changes from `False` to `True` — a single meta-tool surface that can call `file.delete` is, conservatively, destructive-capable, and a client gating confirmation on the hint should not skip it.
- The `otpack` memoize cache singleton (`packages/onetool-pack/src/otpack/cache.py`) gets a bounded `max_size` (LRU already implemented) so `webfetch`'s per-URL page-body memoization (and every other pack sharing the singleton: `context7`, `ot_forge`, `skills`) no longer retains unbounded memory for the process lifetime. (R8 P2)
- (Optional, lower priority) Large-result deflection avoids a third full serialization pass by reusing the already-computed string instead of re-encoding to measure size and re-`json.dumps`-ing raw_result. (R8 P3)
- (Optional, lower priority) The tool registry parses each tool file's AST once at startup and threads the parsed tree through, instead of `read_text` + `ast.parse` twice per file. (R8 P4)

## Capabilities

### New Capabilities

(none — all changes modify existing capability contracts or are internal correctness fixes with no new observable surface)

### Modified Capabilities

- `serve-run-tool`: adds the `isError:true`/`isError:false` failure/success contract (D2) and a per-tool execution timeout (D3) as new behavior; adds parameter-ambiguity refusal to the existing Parameter Prefix Matching requirement (D4); adds nested-execution namespace isolation and a recursion depth guard to Snippet Expansion (D5, D-a2, D-a4); adds serialization-resilience behavior to Robust Result Capture (D7, D8, D9, D10, D-b1); adds explicit empty-command validation (D-a1); adds sanitize-before-store and format-preservation to Large Output Handling (D-b3); adds a tool-annotations requirement recording the `destructiveHint: True` decision.
- `serve-mcp-proxy`: adds downstream result-conversion correctness (EmbeddedResource handling, structured_content fallback, restrained JSON coercion) (D12, D13); adds thread-safe tool listing (D15).
- `serve-server-management`: adds the same-loop guard to `connect_additional_sync`/`disconnect_server_sync` (D3) so a server-control call issued from the same event loop it would otherwise block never deadlocks; adds cache eviction on restart for the proxy pack accessor cache and MCP param-name cache (D14).
- `serve-output-sanitization`: tightens `TRIGGER_PATTERN` so prose mentions are not corrupted (D11); adds sanitize-treatment consistency between trusted error results and `prepare_command` errors (D-b2).
- `serve-stats`: clarifies that `error_type` in run-level and tool-level records reflects the real exception type, not a generic wrapper type (D6).

## Impact

- **Affected code**: `src/ot/executor/runner.py` (`_force_single_quotes`, `_normalize_code`, `prepare_command`, `execute_command`, `execute_python_code`, `_nested_run`, `_map_error_line`, `CommandResult`), `src/ot/server.py` (`run` tool handler, annotations, uvicorn `Config`), `src/ot/executor/param_resolver.py` (`resolve_kwargs`, `_mcp_param_cache`), `src/ot/utils/format.py` (`serialize_result`), `src/ot/utils/sanitize.py` (`TRIGGER_PATTERN`), `src/ot/proxy/manager.py` (`call_tool`, `call_tool_sync`, `connect_additional_sync`, `disconnect_server_sync`, `list_tools`), `src/ot/executor/pack_proxy.py` (`_namespace_cache`, `McpProxyPack._function_cache`, `reset`), `src/ot/registry/registry.py` (AST parse, optional), `packages/onetool-pack/src/otpack/cache.py` (`Cache` singleton bound).
- **Dependency**: none — D2's `ToolError` fix works against the currently pinned FastMCP `>=3.1.1,<4` (installed 3.3.1); no version bump is required or proposed by this change (the floor bump to `>=3.4.1` is owned by `p32-dependency-refresh`, R8 M6).
- **Tests**: new/updated unit tests under `tests/unit/` for each defect (runner normalization, `isError` contract, `resolve_kwargs` collisions, nested namespace isolation, `serialize_result` degrade paths, `TRIGGER_PATTERN`, proxy result conversion, cache eviction, `list_tools` thread-safety, `output_schema is None`); an integration test for the always-`to_thread` non-blocking behavior (concurrent `run` calls).
- **Downstream/out of scope**: FastMCP-native alternatives to the hand-rolled mechanisms here (`run_in_thread=True`, native tool timeouts, `ProxyProvider` delegation, OpenTelemetry tracing, Monty sandbox) are explicitly **not** adopted by this change — see design.md "Own vs. Delegate — Deferred" for the reasoning and re-evaluation triggers. `security-model.md` doc-truth (R8 S1), untrusted-content system messages (R8 S2), and log redaction (R8 S3) are owned by `p22-technical-foundation`, not this change. The FastMCP floor bump and dependency refresh (R8 M6) are owned by `p32-dependency-refresh`.
