# Client projection test vectors (D7 spec)

Authoritative fixtures for the report app's client-side projection — the
control mechanism for D7, consumed by the frontend vitest suite. They are
READ-ONLY for executors: a vector that looks wrong is a stop-and-ask, never
an edit.

| File | What |
| --- | --- |
| `model.yaml` | Synthetic schema-v3 architecture exercising the edge cases: gap reintroduction (`subG`), content revision (`subR`), clip chains (`sysL` → `subL`/`compL`/`iAL`), off-timeline `from`/`until` (`iAB`, `sysL` on `alt`), intra-system interface (`iAA`, a systems-level self-loop), two timelines. |
| `payload.json` | `model.yaml` compiled per report.md "Payload contract (v1)". |
| `vectors.json` | Cases for `state_at`, `diff`, `scope`, `rollup` with expected outputs. |

Provenance (2026-08-23): generated by architect scratch tooling. `state_at`
and `diff` expectations are computed by the authoritative Python resolver
(`_arch/v3/resolver.py`); `scope` and `rollup` expectations implement
report.md "Client projection contract (v1)", whose prose and this data were
written together. Positions use the payload convention (0 = Current,
i + 1 = i-th milestone of the timeline); node keys are `kind:id`.

Regeneration is an architect task (the scratch generator is not kept);
regenerating `payload.json` with the real `build_payload` must reproduce
identical ids and segments.
